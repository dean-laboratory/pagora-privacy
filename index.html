Pagora Privacy Policy

Effective date: November 14, 2026

This Privacy Policy describes how the Pagora application for Android (the "Application"), developed by pqzmggg (the "Developer"), handles information in connection with its use. The Application organizes the PDF and ZIP (CBZ) books stored in storage services the user connects (Google Drive, Dropbox, OneDrive, and WebDAV or SFTP servers such as a NAS) into a library and displays them for reading.

1. Information Collected by the Developer

The Developer does not collect, receive, or have access to any personal information of users. The Developer operates no servers for the Application, and the Application requires no account other than the user's own accounts for the storage services the user chooses to connect. Information described in this Policy is processed on the user's device or exchanged directly between the device and the following parties: the storage services the user connects (Sections 2 and 3), the AI company the user chooses (Section 5), Google AdMob for the advertising banner (Section 6), and Google Play for purchases (Section 7). The Application contains no analytics or crash reporting components of its own.

2. Storage Services and Book Data

When the user connects a storage service, the Application signs in through that service and receives access limited to what it needs:

  1. Google Drive: read-only access to the user's Drive (drive.readonly). If the user turns on sync across devices (Section 3), also access to the Application's own hidden app data folder (drive.appdata).
  2. Dropbox: read access to file metadata and contents and basic account information (files.metadata.read, files.content.read, account_info.read). If the user turns on sync across devices, also write access (files.content.write), which the Application uses only for its own folder /Apps/Pagora.
  3. OneDrive: read access to files and basic profile information (Files.Read, User.Read, offline_access). If the user turns on sync across devices, also access to the Application's own app folder (Files.ReadWrite.AppFolder).
  4. WebDAV and SFTP servers: the server address, user name, and password the user enters, and for SFTP the server's host key fingerprint that the user confirms.

The Application does not receive or store the user's Google, Dropbox, or Microsoft password. Sign-in tokens and the passwords of WebDAV and SFTP servers are encrypted with an Android Keystore key and kept only in the Application's private storage on the device.

With this access, the Application uses the following data solely to provide its features to the user:

  1. The names, folder locations, sizes, modification times, checksums, and thumbnail images of PDF and ZIP (CBZ) files, and the names and structure of folders in the folders the user chooses to scan, in order to find books, build the library, and sort books into categories on the device.
  2. The contents of the files that the user chooses to download, in order to keep them on the device and display their pages. When the user has read most of a volume in a series, the Application may download the next volume of the same series in advance.
  3. The first part of PDF files and parts of ZIP (CBZ) files, in order to create cover images and to read the text at the beginning of books for sorting them.

To sort books whose category cannot be determined from their file names, the Application reads the text at the beginning of the book (text contained in the PDF, or text read from the cover image by on-device text recognition) and may give book titles and this text to an on-device language model that the user chooses to download. This processing takes place entirely on the device; unless the user chooses an external AI (Section 5), titles and text are not transmitted to the Developer or to any other party.

In Google Drive, the Application looks by default only at files in the user's own My Drive; files and folders that other people have shared with the user are read only when the user selects those folders. The Application does not create, modify, move, or delete the user's book files in any storage service. Book data is requested by the device directly from each storage service and is not transmitted to the Developer.

The Application's use and transfer to any other app of information received from Google APIs will adhere to the Google API Services User Data Policy, including the Limited Use requirements. Data from storage services is not used for advertising, is not sold, and is not read by any person.

3. Sync Across Devices (Only When Turned On by the User)

For each connected storage service, the user may turn on sync across devices to keep reading positions, bookmarks, and book categories the same on the user's other devices. When it is on, the Application writes small sync files containing this information (with the file identifiers and titles of the books in that storage and, with categories, the text read from the beginning of those books) to an app-only location in that same storage: the hidden app data folder in Google Drive, the app folder in OneDrive and Dropbox, or a .pagora folder inside the folder the user chose on a WebDAV or SFTP server. The sync files are exchanged only between the user's devices and the user's own storage; they are not sent to the Developer. The user may turn sync off at any time, and may delete the sync files from the storage.

4. On-Device AI Models

When the user chooses, the Application downloads an on-device language model and a list of available models. These downloads contain no information about the user.

5. External AI (Only When Chosen by the User)

On the Application's AI classification screen, the user may add an external AI model with the user's own API key and choose it as the classification model: Claude (Anthropic), ChatGPT (OpenAI), Gemini (Google), Grok (xAI), or EXAONE (LG AI Research). This feature is not used by default.

  1. Information sent: the titles of the books to be classified, part of the text at the beginning of those books (up to 80 characters per book), and the list of categories needed for the request. Account information, the book files themselves, and reading history are not sent.
  2. Recipient: the API of the company the user has chosen. The device sends requests directly to that company, without passing through the Developer. The information sent is handled under that company's privacy policy (Anthropic, OpenAI, Google, xAI, LG AI Research) and the API terms the user has agreed to with that company. Under some free tiers, the company may use what is sent to improve its services (for example, the Gemini API free tier outside the EEA, Switzerland, and the United Kingdom); the Application tells the user this when Gemini is chosen.
  3. Purpose: to determine the categories of the books. The answers (categories) are stored on the device and, if sync is on, in the sync files described in Section 3.
  4. API key: encrypted with an Android Keystore key on the device and kept only in the Application's private storage; it is not transmitted to the Developer. Usage is billed to the account of the API key.
  5. Stopping: the user may at any time switch the classification model back to an on-device model or delete the external AI model, after which no information is sent. When all external AI models of a company are deleted, that company's API key is deleted too.

6. Advertising (Google AdMob)

Unless the user has purchased ad removal (Section 7), the Application shows a banner advertisement at the bottom of its screens using Google AdMob, provided by Google. To show, limit, and measure ads and to prevent fraud, the Google Mobile Ads SDK may collect and process information such as the device's advertising ID, IP address, device and app information, and interactions with ads. This information is sent directly from the device to Google and is not sent to the Developer. The Application does not give AdMob any book data, file names, reading history, or storage account information.

  1. Consent: in regions where consent is required (such as the European Economic Area, the United Kingdom, and Switzerland), the Application asks for consent through Google's User Messaging Platform before ads are requested, and the user can change the choice at any time in Settings > Ad privacy settings.
  2. Personalized ads: the user can reset or delete the advertising ID, or opt out of personalized ads, in the device's settings (Settings > Privacy > Ads, or Google > Ads, depending on the device).
  3. More information: How Google uses information from sites or apps that use its services and the Google Privacy Policy.

7. Purchases (Google Play)

The user may buy "Remove ads", a one-time in-app product, through Google Play Billing. Payment is handled entirely by Google Play under the Google Privacy Policy; the Application and the Developer do not receive payment information. The Application asks Google Play only whether the purchase exists for the user's Google account, in order to hide ads, and keeps the result on the device.

8. Permissions and Their Purposes

  1. Internet access: to sign in to and read from the storage services the user connects, to write sync files when sync is on, to download on-device AI models, to request classification from an external AI when chosen, to show ads, and to check purchases.
  2. Foreground service (data sync) and notifications: to keep downloading an AI model or classifying the library while the user is in other apps, with a progress notification that includes a Stop button.
  3. Advertising ID: used by the Google Mobile Ads SDK as described in Section 6.
  4. Google Play Billing: to buy and check the "Remove ads" purchase.

9. Information Stored on the Device and Its Deletion

For its operation, the Application retains the following information solely in the Application's private storage on the user's device:

  1. The library: the file information described in Section 2, the text at the beginning of books, the categories assigned to each book, reading positions and progress, and bookmarks.
  2. Books that the user has downloaded and cover images, kept as a cache.
  3. Settings, connected storage accounts with their encrypted sign-in tokens and passwords, the external AI settings and encrypted API keys, the ad consent choice, and whether ad removal has been purchased.

Application backup is disabled, and this information is therefore not copied to any cloud backup. The user may delete downloaded books at any time in Settings > Downloaded files, may disconnect a storage service (which removes its books and records from the device), and may delete all information at any time by clearing the Application's storage or by uninstalling the Application. Books that are no longer found in storage are removed from the library 30 days after they disappear.

10. Revoking Access

The user may disconnect any storage service within the Application at any time. The user may also revoke the Application's access on the Google Account third-party access page, in Dropbox connected apps, or on the Microsoft account apps and services page.

11. Disclosure to Third Parties

The Developer does not provide, sell, or transfer any information to third parties. Information is exchanged directly between the device and only the parties described in this Policy: the storage services the user connects, the AI company the user chooses (Section 5), Google AdMob (Section 6), and Google Play (Section 7), each under its own privacy policy.

12. Children

The Application is not directed at children, and the Developer does not collect information from any person, including children.

13. Changes to This Policy

Any amendment to this Privacy Policy will be published on this page together with its effective date.
